# Payment guard diagnostic session

Open **设置 → 想好再买 → 检测自检**, tap **开始记录**, reproduce the problem without completing payment, return to the dialog and tap **停止记录 → 保存文件**. The system file picker chooses the destination. The exported UTF-8 text contains one JSON object per line and can be shared manually. Export is a queued snapshot and works while recording; stopping first makes the session boundary clear.

Recording is off by default, expires after 30 minutes, and retains two rolling segments of about 128 KiB each in app-private no-backup storage. Oldest events can be rotated out. Logs remain until explicitly cleared or the app is uninstalled; user-exported files are separate. The session flag survives process restarts within the time limit when log files exist. A `PROCESS_RESTART` entry marks a restart. Queue overload is counted in `dropped_events`; operating system events, disabled permissions, battery restrictions, and process termination can still cause gaps. No claim of a complete record of every user action is made.

The export is allowlisted: UTC time, elapsed time, supported package/class identifiers, a few fixed click roles, app/device version and permission state, decision codes, node counts and boolean structure flags, and exception types plus app stack frame names. It deliberately excludes node text, typed text, payment amounts, thresholds, merchant names, accounts, passwords, exception messages and arbitrary foreground application names. `VIEW_CLICKED` is logged only for supported packages and non-password events; labels are mapped to a small fixed set without storing raw values. Inspect the resulting file before sharing because app and device identifiers are still present.

## Interpreting events

`A11Y_WINDOW_STATE`, `A11Y_WINDOWS_CHANGED`, `A11Y_CONTENT_CHANGED`, and `A11Y_VIEW_CLICKED` are best-effort accessibility events, not an independent recording of the visible screen. Content events are throttled to at most one per 1.2 seconds. `event_uptime_ms` uses Android uptime, whereas `elapsed_ms` uses elapsed realtime and can diverge after sleep. Both are milliseconds; `time_utc` is for human correlation. If permission, service, or window availability is missing, absence of events does not prove a page was absent.

`NOT_CHECKOUT`, `NO_ACTIVE_ROOT`, `NO_ACCESSIBLE_TEXT`, `NO_AMOUNT`, `AMBIGUOUS`, `BELOW_THRESHOLD`, and `QUALIFIED` are classifier outcomes; node-count fields are aggregate metadata. `numeric_after_label` and `near_sibling` help diagnose split text nodes without recording the numbers. `SERVICE_REQUEST_POSTED` is a queued request, not proof that a prompt appeared. `OVERLAY_ADDED` indicates the system accepted a window request; `OVERLAY_STATE` reports attach/shown state only and does not prove visibility or touch interception. `USER_CONTINUE`, `USER_WISHLIST`, `OVERLAY_TIMEOUT`, `LEFT_APP_CLOSED_OVERLAY`, and `SETTINGS_CLOSED_OVERLAY` document known transitions. An `ERROR` contains exception types and app stack frames but deliberately omits exception messages.

To interpret a returned file, first align `SESSION_START` permissions and lifecycle records, then app transitions and accessibility events, then classifier status and aggregate evidence, then queued request and overlay states. Ask for the reproduction app and whether the test amount exceeded the configured threshold if the status is inconclusive. Never infer successful interception from a class match or an attached window alone.
